# Wiki 材料读取预算

Wiki Agent 为每个事实任务维护一个累计原文字节额度。相同任务的恢复、失败重试和重复读取共用额度，预算不足时任务保持未完成，不生成缺少证据的完成结果。此额度不是 token 计数，也不是模型费用上限。

## 配置与计数

Wiki Agent Provider 的 `maxTaskMaterialBytes` 默认是 33554432 字节（32 MiB），必须是正安全整数。它在该任务第一次预扣时固定；更改配置只影响尚无账本的任务，不自动扩大旧任务的额度。`maxMaterialBytes` 仍限制单次读取，`maxOutputTokens` 仍限制单次模型请求的输出。分析、文件综合、核验和一致性任务分别记账；Page 任务不读取原文。

每次读取先按完整文件或含上下文的完整区间字节数预扣，再访问材料 Provider。重复读取再次预扣；流中断、哈希不符、编码失败、取消和进程退出不退款。预扣量因此可能大于实际返回量，但不会把可能已经返回的原文漏算。工具成功结果同时显示累计预扣与总额度；不按字符密度换算成 token。

账本以 Run id 与 Task id 定位，记录总额度、累计预扣、预扣次数、被拒绝的读取大小及记账起点。`startedAt` 和 `startedAtAttempt` 以前的读取量未知；账本缺失不代表历史消耗为零。SQLite schema v20 在独立表中保存账本，v19 升级不改写 runtime v8 快照或追认历史费用。

## 预算不足与恢复

额度不足的读取不会调用材料 Provider，也不截取前半段正文。拒绝状态持久化后，该任务不能提交 succeeded；已分析的上游任务不回滚，未核验的 Claim 不升级为 verified。后续“执行下一个任务”在扩额前不再启动同一任务的模型 Session。

在“设置 → 记忆与知识”选择项目，打开 `LLM Wiki`，在目标 Run 中展开“材料读取预算”。面板显示任务类型、状态、累计预扣、总额度、预扣次数、被拒绝读取大小和记账起点；可以只看预算不足的任务、刷新或翻页。默认不请求账本，每页最多 20 条；没有账本的任务不会被列为零消耗。

对运行中、失败或取消的事实任务，点击“调整任务额度”，输入新总字节数，再点击“核对变更”和“确认扩额”。核对阶段可取消而不写账本。确认请求绑定当前 Workspace、Run、Task 及完整账本哈希；期间发生预扣、首次拒绝或其他扩额时，Host 拒绝旧确认，页面重新查询，操作者需再次核对。网络错误不自动重复扩额；先检查重新查询的最新额度。扩额不自动执行模型，也不改变任务状态。

本机 CLI 也可用错误信息中的 Run id、Task id 和同一私有数据库查看账本。从已有的 `wiki-plan` 命令输出中可以取得 `runId` 与 `nextTaskId`；该命令在 Catalog 未变化时复用原 Run，不重置账本。

```sh
dsh-memory-knowledge wiki-budget <run-id> <task-id> --db <sqlite-path>
```

需要继续时，操作者可以显式提高总额度：

```sh
dsh-memory-knowledge wiki-budget <run-id> <task-id> --limit <new-total-bytes> --db <sqlite-path>
```

新额度必须严格高于旧额度，并能容纳已预扣量加上被拒绝的那次读取；扩额不会清除累计预扣和次数。随后再次执行 Wiki 任务。原 Session 中断时走恢复，已失败任务分配新 Session；两者都必须重新读取需要的证据，预扣仍继续累计。扩额只向本机操作者和设置页开放，Wiki 模型工具不能调用。CLI 每次按数据库中的最新额度执行单调增加，不使用浏览器的核对版本。

## 持久化与限制

预扣在 SQLite 写事务内核对任务的运行状态和 Session 所有权，再更新账本；多个连接不能同时花掉同一份剩余额度。任务提交在自己的写事务内检查持久化拒绝状态。账本不参与语义快照 hash，也不随快照的删除再插入级联清除；普通预扣只更新一个账本行，不重写整份项目 Coverage。

浏览器查询按 Task id 游标读取账本页，不加载整份 Coverage 或材料。查询和扩额均核对已注册项目的规范路径与 Run 所有权；扩额在同一写事务内校验账本哈希和当前任务状态。返回值不含本机路径、源码或 Agent Session id。切换 Workspace/Run 会销毁旧确认状态，旧请求返回后不覆盖新项目。哈希从现有账本计算；项目知识版本引入 SQLite schema v21，但材料账本格式与 Wiki runtime v8 不变。

此预算只约束一个 Task 交给模型的原文预扣总量。不包含 Claim 上下文、提示词、历史上下文的重复输入、输出 token、整个 Run 的总费用或本地缓存准备所需的 I/O。大量任务可以累计超过单任务额度；按问题定位更小的证据范围、跨任务复用和 Run 级费用控制仍需继续实现。预扣不是成功阅读证明，只有完整材料校验及现有 Citation 规则通过后才能提交事实。
