# 知识生命周期与实施设计

状态：目标技术设计，分阶段实现。本文落实[产品设计](product-model.md)；当前行为见[运行说明](runtime.md)。

日期：2026-09-09

## 1. 领域、记录与所有权

记忆和知识具有独立的 Service、记录、检索结果及 Session 上下文段落；允许共用 SQLite、证据解析和 Workspace 映射。先在现有 Bundle 内按职责划分，不为每个模型单独增加 npm 包，不修改 AgentLoop。

| 记录 | 必需内容 | 所有者与用途 |
|---|---|---|
| MemoryEntry / MemoryRevision | 稳定 id、个人/项目范围、分类、正文、条件、来源、可见性、生命周期、替代/冲突关系 | 记忆服务；候选被接受后转成独立长期条目 |
| AnalysisSpec | 项目、Source 版本向量、范围与排除、分析问题、必需阶段、策略版本、预算 | 分析调度器；固定本次分析承诺 |
| AnalysisQuestion | 问题、适用领域、必查材料/流程、已调查证据、结论状态、未知原因和影响 | 分析与回查任务；提供可核查的业务完成清单 |
| MaterialExposure | 原文区间与哈希、任务/尝试、Session 消息与实际请求引用、发送结果、分析结果引用 | 阅读审计；区分本地已读取与实际模型输入 |
| KnowledgeObject / ObjectRevision | 稳定 id、对象类型、版本化字段、事实与关系引用、来源、身份沿革 | 知识服务；实体、规则、流程、步骤、模块、接口、数据及文章 |
| Claim / Citation / Conflict | 主张、准确来源、支持/反驳关系、核验结果与冲突双方 | 证据账本；独立于文章组织 |
| GeneratedVersion | AnalysisSpec、完成报告、不可变对象/证据清单、生成器/规则版本 | 分析输出；人工保存不改写它 |
| HumanRevision | 修订 id、基于的生成/生效版本、目标对象与字段、操作、前值指纹、作者来源、时间 | 编辑服务；保留修改、删除、恢复和冲突处理 |
| EffectiveVersion | 生成版本、纳入的人工修订、合并冲突、对象修订清单、投影/索引版本 | 读取服务；用户视图和 Agent 使用同一版本 |
| FreshnessAssessment | 生效版本、目标 Source 向量、变化证据、受影响对象、检查状态 | 新鲜度服务；不改写历史生成事实 |
| KnowledgeSelection | 项目/范围/Source 目标、选择修订、当前分析代际/Run、自动或固定模式、停用记录 | 本机版本选择；不按任务完成时间或分支名称决定新旧 |

其中 MemoryEntry、MemoryRevision、GeneratedVersion、EffectiveVersion 和 KnowledgeSelection 已完成第一阶段持久化及运行接口；HumanRevision 已完成面向 Wiki Page 的正文替换与追加说明纵切，包括幂等保存、版本并发校验和同一生效版双视图投影。其余名称仍是设计名，不代表已有完整接口。当前版本清单直接引用既有 Page、Claim、Citation 与 Conflict，尚未形成完整 KnowledgeObject 或 FreshnessAssessment；现有 HumanRevision 已进入只包含当前 EffectiveVersion 的独立本地全文索引，但尚未进入 Agent 默认查询、对象身份沿革或三方合并。复用现有 KnowledgeSpaceId 表示稳定项目身份，KnowledgeSourceId 表示材料源；Workspace 与本机绝对路径只是本地绑定。用户看到的项目名称可改，身份不随改名或迁移机器变化。

状态不能挤进一个 `verified` 字段：执行状态、结论类型、核验状态、来源和新鲜度分别保存。人工陈述可以生效而尚未由代码证实；模型推断不能因为进入生效版本就升级为事实；有冲突的已完成版本仍可以使用，但必须携带冲突。

生成文章按内容块引用语义对象或 Claim。事实块必须有出处，推断与未知有明确标记；连接段落不能夹带无来源的新事实。人工正文是有作者来源的内容块，不冒充代码结论。文章树与语义关系分开：一个规则可被多个页面引用，语义图允许业务循环，页面树拒绝结构循环。

## 2. 完整深度分析的完成标准

### 2.1 固定分析承诺

规划时记录所有 Source 的不可变版本、Catalog 内容身份、范围、排除规则、问题清单和检查策略版本。默认范围是整个已注册项目；操作者明确选择子模块时只能得到标为局部的分析，不能覆盖全项目正式知识指针。

问题清单至少覆盖：项目目标与术语、用户/系统入口、核心实体与状态、规则及约束、主流程、异常/重试/取消/补偿路径、持久化与外部接口、配置及运行差异、实现与测试位置。模型从全项目目录和材料发现具体问题；不适用项必须给出证据或明确的范围理由，不能机械生成通用标题即算完成。

分析中新发现的必需问题和跨模块回查任务追加到同一可审计清单。关闭前固定清单修订号；任务仍可新增或尚未处理的版本不允许生成完成报告。范围扩大创建后继 AnalysisSpec 并重新检查出域许可；范围缩小创建另一个明确标为局部的 Run，不能删除原 Run 的失败项以达标。

### 2.2 必须通过的检查

| 检查 | 通过条件 | 不通过时 |
|---|---|---|
| 来源与目录 | 所有 Source 版本固定，目录无未解释遗漏，纳入/排除可审计 | 阻塞并保留草稿 |
| 纳入材料阅读 | 所有纳入的文件/核心区间有完整读取校验、实际模型输入及成功分析结果的关联；复用项有适用性证明 | 继续分析；缺读、仅送摘要、发送未确认、deferred 或失败不能折算为已分析 |
| 项目问题 | 每个必需问题完成调查，关联结论或“调查后仍未知/冲突”及其证据 | 未调查、证据任务失败或预算中断保持未完成 |
| 跨模块理解 | 每条纳入的核心流程说明入口、顺序/分支、状态与数据、异步和异常路径，并回查对应实现/测试 | 缺步骤、只凭 import 推断流程或遗漏必需回查时继续分析 |
| 证据及一致性 | 事实/推断引用有效；关键关系和配置/测试矛盾完成定向回查；必需核验任务无遗漏 | 无效引用、核验截断、必需候选未处理阻止完成 |
| 知识可读取 | 对象引用无悬空、两个视图所需内容齐全，未知/冲突/省略标记可投影 | 保留生成草稿，不切换当前版本 |

空文件可以形成明确的空分析结果；二进制、供应商依赖和生成物按事先确定的范围规则处理。语言未知或没有 AST Provider 不是排除理由。必需业务材料不可读取时应阻塞；只检查文件哈希、分片工具调用成功或模型声称“已理解”都不足以证明分析完成。

“调查后仍未知”必须保存调查任务、已查材料、缺失信息和影响。例如代码未记载业务动机可以保留未知；没有额度读取退款逻辑则属于未完成。外部系统未纳入时说明接口可见行为与外部内部实现的知识边界，不能编造该系统细节。向操作者提问时一次问一个具体问题，回答作为有来源的业务补充。

完成报告由 Host 根据持久化记录计算，模型只提交问题调查与语义结果，不得自授完成状态。检查保证过程和证据要求，不证明语义零误差，也不要求穷举全项目任意两条 Claim 的组合；需要回查的集合由版本化策略和本项目问题共同确定。集合内的预算截断不能解释为检查通过，集合外的已知覆盖局限必须披露。

### 2.3 实际模型输入与非循环证据

MaterialExposure 将 Source/文件/区间及内容哈希关联到任务尝试、durable Session 消息、实际模型请求和对应的提交结果。只有已经过最终请求装配的原文才能登记为该请求的材料输入；Session 中出现过但被压缩、截断或未发送的正文不算本次输入。输入元数据引用已有受保护的消息正文，不在另一账本复制源码。跨多个请求的输入区间可以合并计算覆盖，但必须各自关联成功分析结果，不能只因字节区间并集完整就判定分析完成。

请求尚未发出、发送结果不确定、仅缓存准备成功或模型只收到摘要时，材料输入保持待确认。保留这些尝试和已发生预算，不能用规划范围补出实际送模范围。一次成功分析可以明确产出“该范围无相关结论”，不强迫每个区间编造 Claim；该结果仍要关联实际输入和任务。复用的分析继承旧输入记录并附当前证据与策略适用性检查，不伪造新请求。

原文输入记录只证明材料参与成功请求及后续分析提交，不能证明模型逐字关注或理解正确；语义深度仍通过项目问题和独立回查验收。实现须使用 DSH 公开、可持久化的请求/Session 接口验证最终输入；接口无法提供必要证据时报告不支持该完成检查，不能用工具成功状态代替。

证据类型区分原始源码/文档、明确的人工业务补充、模型生成对象和人工修订。支持链必须无环，并最终落到匹配 Source 版本的原始材料或有作者/范围的业务补充；后者仅支持其声明的业务意图，不独立证明源码实现。旧 Wiki、生成 Claim 及模型建议记忆只能作为上下文或复用线索，不能独立证明新事实。候选被接受也不能擦除其模型来源。核验发现循环或来源缺失时拒绝对应支持关系，安排回查或明确记录调查后的未知，不能升级为 verified。

## 3. 运行状态与自动激活

### 3.1 目标选择与分析代际

本节的“目标”由稳定项目、分析范围和固定 Source 向量组成，不是两个展示 Tab；用户与 Agent 视图共享同一目标。每个目标保存递增的分析代际和当前目标 Run，Workspace 的当前 Source 选择另保存递增的选择修订。显式发起替代分析时原子分配新代际；重复规划、任务恢复和重试沿用原代际。取消或失败不会恢复被替代 Run 的激活资格，继续采用较早成果必须是操作者的显式选择。

自动激活必须同时满足当前目标 Run/分析代际未被替代、版本未停用及选择策略允许。较早 Run 晚完成仍可封存 GeneratedVersion，但只能作为历史成果，不能通过读取最新指针重新获得激活资格。另一 Source 快照的 Run 可以完成自己的目标版本；只有 Workspace 的当前目标与选择修订仍匹配时才能更新当前视图，不能把当前分支切回它分析的分支。

### 3.2 准备与原子切换

Run 分别记录执行状态（计划中、运行中、暂停、阻塞、失败、取消、分析完成）、当前阶段和完成报告；版本另有准备中、可激活、已激活及激活失败状态。UI 明确区分“分析完成，正在准备知识”“知识准备失败”和“完成，可使用”，仅激活成功才显示最终成功状态，不把索引失败提示成人工待审核。

暂停、进程退出和失败保留成功任务及证据。恢复继续同一 Run，失败重试继续累计预算；任务 Session 和尝试记录可追溯。主动取消不自动重启，也不删除草稿。后继增量分析不撤销上一个生效版本。

自动激活协议：

1. 对固定的清单修订号计算完成报告，封存 GeneratedVersion。
2. 读取当前人工修订头，按第 5 节规则合并为候选 EffectiveVersion；未解决冲突和待关联修订仍保留在该版本中。
3. 准备该版本的用户投影、Agent 对象查询和基础文本索引，校验对象清单及代际一致性。
4. 在短事务内校验 Run 所有权、目标 Run/分析代际、选择修订/模式、停用记录、当前生效指针及人工修订头，再切换目标的唯一生效指针；并发人工保存后必须重做合并，分析被替代或选择改变则只保留历史成果，不覆盖当前视图。
5. 发布版本变更通知。崩溃发生在切换前则继续旧版，切换后按同一版本恢复，重复激活幂等。

只要条件满足就自动执行，不增加用户审核或逐卡接受步骤。合并、索引准备和激活是确定性本地操作，不调用 LLM；出域许可限制前面的模型分析，不是已完成版本激活的前置确认。分析阶段缺少许可时暂停相应任务并保留草稿，不能跳过任务宣布完成。索引构建或落盘失败时保留旧指针，报告具体失败并允许重试；重试次数、退避和并发为经过校验的配置。

一次读取在开始时固定 `effectiveVersionId` 和新鲜度检查版本，分页游标及双 Tab 导航都携带它们。切换期间的在途请求可以完成旧版响应，但标明版本；新请求读取新版。客户端切换 Workspace 后丢弃旧响应，不能把两个项目或两个代际拼接。

同一项目/目标的生效指针在事务提交时更新，并递增本机切换序号。保存和具备激活资格的分析按该提交顺序串行生效，切换序号不能替代分析代际校验。保存成功响应发出后启动的默认查询读取该版本或包含其修订的后继版本；如果其后发生停用或目标切换，则返回相应状态，不能回退到更旧正文。显式固定历史版本的读取例外，但必须标明历史；客户端按选择修订与切换序号拒绝迟到响应覆盖新版，不能对不透明版本 id 或时间戳排序。

### 3.3 整版停用与回退

操作者可以显式停用选定生成版本及依赖它的生效版本，记录原因、影响目标与操作来源；本机事务更新停用记录及选择修订。新的默认查询立即返回停用提示，不自动降级查询另一旧版或草稿。历史查看、原始材料查询和人工修订仍保留，后续模型请求按第 4 节追加失效提示。整版停用与任务暂停分别提供：停用不删除成果，也不隐含已取消正在发生的模型调用或费用。

停用规则优先于自动激活、索引重建和重复导入；相同被停用版本不能通过生成新的生效版本 id 绕过它。知识已经共享时，本机停用不会撤销其他成员的副本；共享停用通知必须显式导出，团队接收后仍需执行本机适用性检查。

回退请求选择一个可用的旧生成基线，基于当前人工修订头重新合并并预览差异、冲突、待关联修订及新鲜度。操作者确认后按选择修订、当前指针和人工头校验，原子建立新的生效记录；不直接把指针跳回旧 EffectiveVersion，不丢弃回退后仍需保留的人工修改。若要连人工内容一起恢复，应另走明确的修订恢复操作。目标被停用、依赖缺失或检查失败时拒绝回退并保留当前状态。

回退后的目标进入固定模式，后台 Run 继续保留成果但不能替换它。恢复自动更新或重新启用被停用版本是明确、可审计且有版本校验的操作者动作；重新启用也不跳过新鲜度检查。回退旧源码快照只形成有版本标签的历史视图，未经变化评估不能作为当前源码事实。在自动模式且版本未停用时，满足条件的新生成版本仍自动激活，不增加逐版审核；固定模式下必须先显式恢复自动更新。

## 4. 编辑、保存与两种视图同步

| 编辑方式 | 保存后的立即效果 | 不承诺的效果 |
|---|---|---|
| 结构化修改规则、步骤、关系、代码锚点 | 新字段和人工来源同时进入用户与 Agent 视图；旧支持证据和下游派生结论按依赖失效 | 不自动证明源码符合新规则 |
| 修改知识正文 | 新正文立即可读、可检索；所属内容块引用的旧主张/关系标记待复核 | 不在无 LLM 情况下自动理解任意自然语言改动 |
| 追加说明 | 新建独立人工说明，保留原分析并在两个视图展示关联 | 不暗中替换原规则，也不推断新的关系 |
| 调整标题、顺序或布局 | 更新展示元数据，稳定语义身份不变 | 不提升事实可信度 |

编辑器先让操作者选择“修改正文”或“追加说明”，不能靠无模型的字符串规则判断其业务含义。正文编辑的保守失效范围是被编辑块引用的对象及已知下游依赖；无法准确定位块时扩大到所属文章引用集合。失效不删除历史；Agent 同时看到人工正文和待复核提示，不继续执行被遮蔽的旧关系。自由说明参与检索，不自动成为工具指令。

保存阶段只做字段替换、已存依赖关系的失效传播、确定性渲染和文本索引，不发现新的业务关系或重新解释正文。依赖检查未完成时，受影响集合先整体标记待复核；后续分析收窄失效范围，不能为了立即保存而假定旧关系仍正确。

代码锚点的路径、范围和内容身份可以本地校验，但“指向有效代码”不等于“代码支持新结论”。人工选择旧 Citation 时保留其历史用途，新事实的支持关系必须重新核验。用户不提供源码证据也能保存，并清楚标为人工来源。

保存请求包含当前项目/视图、基于的生效版本、目标对象修订、操作内容及幂等请求 id。事务校验当前指针、对象版本和完整性，同时保存 HumanRevision、受影响的 EffectiveVersion 清单、必要文本索引及新指针；未修改对象引用旧的不可变修订，不复制整本 Wiki。保存成功返回新版本，后续新请求必须可查询到它。失败不返回成功，不出现“正文已保存但 Agent 仍默认召回旧正文”；客户端保留编辑内容。

基础内容和查询一致性不依赖异步语义索引。昂贵的图布局或可选向量索引稍后生成时必须标记准备中，并读取当前结构化对象/文本作为回退，不能返回旧代际结果。由 LLM 进行的局部语义对齐是独立任务，受授权与预算控制；它基于修订 id 生成待比较结果，不静默改写人工正文或关系。

网络超时后以同一请求 id 查询或重试，返回原保存结果；同 id 不同内容拒绝。旧版本编辑遇到并发保存返回冲突及最新版本，不使用最后写入者覆盖。恢复历史是引用旧内容的新修订，不把指针退回从而抹去后续历史。已有 Session 的旧召回不可改写；同一 Session 下一次模型请求前，对曾注入且现已替代、删除或失效的条目追加模型可见的 Session 消息，包含旧引用、当前状态及有权限读取的新内容或查询入口，而不仅写 Recall Trace 元数据。不能保证模型忘记已经看过的旧文本。

## 5. 稳定身份与重新分析合并

首次发现语义对象时分配稳定 id，后续 Run 通过前版对象及其证据、类型和业务上下文提出延续映射。标题、slug、文件位置和当前 Run id 只作为定位线索。字段和关系也要有稳定引用，才能判断不同编辑是否重叠。

身份沿革记录延续、重命名/移动、拆分、合并和退役。确定的引用或内容身份延续可复用；模型相似度或名称相近只能形成待核对建议。拆分/合并要保存旧到新对象集合，逐条判断人工修订的目标，无法唯一关联时保留待关联而非丢弃或自动广播到所有新对象。

合并使用三个输入：人工修改时的生成基线、所有尚生效的人工修订、新生成版本。按对象和字段比较，不只比较整页文字。

| 比较结果 | 合并行为 |
|---|---|
| 只有模型基线变化 | 使用新生成值 |
| 只有人工变化 | 保留人工值及来源 |
| 双方改动不相交 | 合并，分别保留来源 |
| 双方改成相同值 | 保留人工审计与新证据，避免重复冲突 |
| 同字段/关系存在不同改动 | 保留人工值、新分析值、原基线及冲突，Agent 查询成组返回 |
| 原对象删除、拆分或无法关联 | 保留待关联修订；不让它从搜索和历史消失，也不指向另一个同名对象 |
| 人工删除但新分析仍生成 | 保留删除覆盖；出现实质新证据时提示冲突，不静默恢复对象 |

重新分析可完成并激活包含冲突的版本。用户视图可以优先展示人工正文，但必须同时显示冲突提示和新证据入口；Agent 不把默认显示顺序当作真伪裁定。冲突解决是明确的新修订：保留人工值、采用新分析或填写另一值，并记录处理对象和基线。派生关系的重新核验也不能把人工来源改标为机器独立验证。

## 6. Source 版本、分支与 Git 共享

### 6.1 版本选择和失效

Source 版本向量包含所有材料源的稳定 id、不可变 commit 或内容快照、排除生成知识文件后的内容身份。跨仓流程同时引用各仓版本，不虚构一个全局 Git commit；这只能证明这些快照组合下的项目理解，不能证明它们曾同时部署。分支名只是本地选择提示，不是内容身份。

本机保存 Workspace/checkout 到项目及所选 Source 向量的映射。切换分支、worktree 或 Source 组合后重新解析，默认只能使用版本匹配或完成变化评估的知识。无匹配版本时显示缺少当前知识，可显式查看历史版；不把上一分支版本作为当前事实。第一版优先支持固定 Git 快照，dirty/untracked 不能冒充已分析；可以明确选择已提交快照，但必须在 UI 与 Agent 结果中标明不包含工作树变更。

分析期间代码前进不重启固定快照任务。版本可以针对该快照完成，在第 3 节的目标与选择检查通过后激活；激活不代表相对当前工作树仍然 fresh。两个 Tab 使用同一 Source 差异评估：用户可查看带过期标记的正文，默认 Agent 结果按下表逐对象过滤；只要部分对象过期，也不能把整版概括为当前已验证。无法计算变更或依赖范围时标记 freshness unknown。未变化对象只有在证据和必要依赖均匹配后才可复用，不因正文哈希未变就忽略配置或调用方变化。

项目打开、Workspace/checkout 切换、导入、激活/回退/重新启用前，以及默认知识查询和自动召回前，Host 检查当前 Source 选择、commit、工作树状态及范围配置。检查结果与本次读取快照绑定；检测到变化时递增选择修订，使旧异步评估失效。文件监听只用于提前失效，不是保持 fresh 的唯一依据。检查失败、范围超预算或无法验证工作树变化时先返回 freshness unknown，再按需安排有界变化评估，不能继续沿用缓存的 fresh。

变化评估必须基于不可变内容身份或完整校验的工作树快照，不能仅凭未变化的大小/mtime 声称内容相同。查询装配后再次检查所观察的 Source 标识，发现变化则重试或返回未知；结果记录检查对象和时点，不声称 SQLite 与外部 Git/编辑器操作构成原子事务。显式查看旧快照不受当前工作树变化中断，但始终标为历史视图。

来源、语义核验与源码新鲜度按下表组合；人工保存不能清除 source freshness，也不能把待复核关系重新变成当前实现。

| 内容与状态 | 默认查询行为 |
|---|---|
| 证据匹配且已核验的生成事实 | 作为带版本及证据的当前事实返回 |
| 人工修订，来源依赖尚匹配 | 返回人工说明/修订及核验状态，不自动标为源码已验证 |
| 人工修订依赖 stale 或 freshness unknown 的对象 | 可返回带原 Source 版本及醒目过期/未知提示的人工说明；基于旧证据的关系不作为当前事实返回 |
| stale 或 freshness unknown 的生成事实/派生关系 | 返回缺口与回查入口；正文仅在显式历史/诊断读取中提供 |
| 不声称描述代码、无源码依赖的独立人工业务补充 | 按自身适用范围与来源返回，不因项目任意文件变化而失效，也不能独立证明实现 |

正文更改涉及的旧关系继续携带待复核及过期状态；跨分支关联失败时修订留在原目标或待关联集合，不自动复制为新分支事实。以上规则与预算、可见性和停用状态一起执行，冲突双方不得因其中一方过期而被静默裁定真伪。

### 6.2 可共享文件与本地数据

项目知识和项目记忆先本机生效，操作者显式导出选择的版本形成可审查 diff；不自动 add、commit、push。多 Source 项目可以先有本地组合知识；只有需要共享组合知识时才要求明确的 Git 知识根，不擅自写入各 child 仓库。

建议的新格式按对象/修订分文件，清单引用不可变记录；以下是目标布局，不是现有初始化命令的输出：

```text
.dsh/knowledge/
  manifest.json                 项目、Source 身份与格式版本
  memories/<id>/<revision>.json 可共享项目记忆及删除记录
  objects/<id>/<revision>.json  生成知识对象
  evidence/<id>.json            可移植证据及冲突
  revisions/<id>.json           获准共享的人工修订
  versions/<id>.json            生成/生效版本清单与完成报告
  heads.json                   共享版本选择，不代表任意分支当前状态
  wiki/                        可重建 Markdown 投影
```

默认导出选定生成/生效版本及其必要依赖闭包，包括被引用的对象修订、证据、获准共享的人工历史、合并基线和删除/停用记录；不会自动导出所有中间 Run、请求输入账本或无关历史版本。相同对象内容和来源未变化时复用原修订，证据去重需包含 Source/版本/范围身份，不能只凭正文相同合并不同来源。依赖清单流式遍历，重复导出不产生重复 payload。

导出前显示文件总量、总字节及新增/修改规模，按可配置的文件数、目录规模和字节限制检查；超限停止并说明原因，不截断引用后继续声明完整。发布验收记录代表性多轮分析的文件增长、重复导出增量、导出/导入和 Git checkout/diff 耗时。只有通过该规模验收才能宣称支持对应大项目；分片目录或批量记录格式根据测量决定，第一版不新增专用存储引擎。

导出选择不等于删除历史：已共享但本次未选中的旧记录不自动清除；Git 中的回收须显式预览并检查仍被共享版本、人工修订或合并基线引用的记录。本机持久历史的保留策略与可重建缓存分开，不能为了减少文件数把唯一人工历史当缓存删除。

不共享 SQLite、索引、材料缓存、完整任务 Session、个人记忆、私有项目修订、凭据和本机路径。导出前检查所有间接引用：移除私有覆盖后从生成基线重建共享投影，不能只删来源标签却把私有正文留在文章中；确需共享某个人工补充时显示内容和可移植来源供操作者确认。共享 evidence 只保存必要的路径/范围/内容身份与可公开说明，不自动打包源码。内容敏感检查和路径检查分别执行。

生成基线也可能依赖私有业务补充，不能默认它全部可共享。来源可见性沿 Claim、关系和文章传播；若移除私有依赖导致事实无证据或完成报告不再成立，应拒绝导出为完整知识，或显式导出标为局部资料的投影。不能沿用原完成报告给脱敏后的不完整版本背书。

导入先在暂存区验证版本、对象引用、哈希、完成报告和来源适用性，再事务切换本地投影。缺文件、未知必需 schema、同 id 不同内容或尚有 Git 冲突标记时拒绝切换，保留当前可用版本。导入不把团队声明当作本机独立核验；缺少源码时可查看带来源缺失标记的文档，但不能称为当前源码已验证。

团队和本机都有新修订时按共同基线合并，禁止按时间戳挑一边。同一对象修订 id 内容必须一致；跨机器新增修订使用独立 id 和父修订，避免两个成员同时创建相同序号但不同正文。撤回共享或逻辑删除不能擦除其他人的 Git 克隆、历史 Session 或备份，彻底清除敏感内容另走显式清理流程。

## 7. 记忆的生效、冲突与删除

默认自动提取策略保持候选审核：用户对话中的明确表达与模型语义推断分别标明来源，但都不直接成为活跃记忆。用户在编辑器明确新建/修改并保存直接生效；接受候选原子创建长期条目并记录候选关联，候选去重和提取断点继续独立保存。是否扩展“明确请记住即自动生效”是以后可配置策略，不在此次知识自动激活中顺带打开。

长期条目采用个人/项目范围与偏好、约束、经验、方法、决策分类，保留适用版本、环境和失效条件。活跃、废弃、删除是生命周期；冲突关系单独保存，不能因为参与冲突就失去历史。更新使用新修订和替代关系，已替代正文不再默认召回。个人库第一版只保存在本机；项目条目可以本机私有或显式共享，约束的提出者不能因导入 Git 就变成系统授权。

冲突处理先检查条件和主张类型：互不重叠的环境约定可以并存，约束与实现不一致应同时呈现“要求/现状”，同范围的互斥约束需操作者澄清。重复、替代和矛盾不能只靠 FTS 分数或更新时间决定；模型提取的新冲突作为候选提示，不自行废弃已接受内容。冲突组检索返回双方及原因；预算容不下时返回可展开的冲突摘要，不仅返回一条命中。

废弃、删除、恢复与修订在同一事务更新基础文本索引。删除生成 tombstone，默认列表/搜索/召回不返回正文，历史页可按明确操作读取并恢复；共享的删除记录防止同步复活条目，重复候选提取也不能越过删除决定重新激活。缺文件不同于逻辑删除，导入不完整不能删掉本地条目。彻底删除另需说明本机历史、Session 与 Git 的清理范围；本设计不暗中重写这些历史。

记忆列表支持个人/项目、分类、标签和生命周期筛选；详情页按需展示来源、适用条件、修订时间线、替代/冲突与知识关联，图形与可展开列表使用同一有界结果。删除正文只在明确的历史查看中返回，当前详情不能借关联图泄漏它。

最近召回记录来自本机持久化的模型输入，显示当时条目修订、项目、时间和 Trace 入口，不把查询命中或候选排名当作实际注入，也不把注入次数当作正确性或遵循率。来源对话仅在操作者有权限且原 Session 可用时展开；共享资料使用可移植说明，原会话不可访问时显示缺失，不暴露 Session id、正文或他人的使用记录。时间线、关联和召回记录均分页，优先实现单条关系检查而非全库大图。

## 8. 大项目的成本、调度与存储

### 8.1 理解与复用

全项目完整首次分析必须处理全部纳入材料，字节校验和模型语义阅读分开计量。完整阅读有无法凭摘要消除的首次成本；展示预计规模及可配置预算，达到上限暂停。用户可选择先看草稿或另建局部分析，产品不能自动降级成抽样却维持“全项目完成”标记。

Catalog 以流式记录写入、计数和建立索引；大文件以语言无关区间处理。项目问题指导跨任务定向阅读，Host 可为相同 Catalog 内的证据追加有界材料分配，并记录授权来源；目录搜索本身不授予材料访问。外部来源或新 Source 必须经过新的范围和权限检查。

分析分片产生可追溯事实，模块综合和跨模块流程保留原始证据索引；上层发现缺口时按问题回查原文，不把所有下层引用无差别重复传入每次综合。复用身份包含内容、必要依赖、分析/提示词/校验策略版本和相关人工修订。全文或整个 Run 变动不应让所有无关对象失效；证据不足以判定时保守重查。

### 8.2 三套独立额度

1. 材料预算：单次读取和任务累计原文字节，沿用[当前任务账本](wiki-material-budget.md)的不退款预扣语义。
2. 模型预算：记录每次实际请求的输入、输出、可获得的缓存用量，包含提示词、历史上下文和工具结果的重复输入；按 Run 汇总并保留尝试和请求 id。
3. 系统资源预算：目录元数据、缓存磁盘、本地 I/O、对象查询返回量、任务并发和超时，分别配置，不能当作 token 节省证明。

模型请求前通过持久事务预留可用额度，包括可计算的完整输入与最大输出。支持可靠 tokenizer/Provider 上限时才能提供对应计量口径的硬限制；否则显示估计口径并使用保守预留，无法建立安全上界时暂停后续自动请求，不能伪称精确硬费用上限。价格缺失时只报告 token，不编造金额。

完成请求后以 Provider usage 结算；无 usage、超时或崩溃留下未知用量及未释放预留，除非有证据证明请求未发出，不能自动当零退款。重试算新请求，恢复不清零；并发请求不能花同一份余额。超预算停止发起新请求，保留已经发生的真实消耗。扩额需要操作者确认且不修改历史账本，模型不能自行扩额或更改停止条件。

数据出域和预算是两种授权。默认 `ask`，可按任务确认；支持整次分析自动推进时，必须由操作者明确授予绑定该 Run、Source 快照范围、Provider 路由和预算的许可。换 Provider、增大数据范围或扩额分别重新检查；`deny` 始终不调用远程模型。用户编辑保存不触发模型请求，后台语义对齐不继承一次普通保存的出域许可。

### 8.3 增量持久化与恢复

Task、Coverage、对象修订、证据和关系分别按稳定键保存。每次提交仅更新任务及受影响行、相关计数和依赖，不调用“删除 Run 后重插全部子表”的保存路径，也不为预算读取/进度轮询重建全量快照。对象/任务 revision、Session 所有权和数据库事务共同防止重复提交及旧任务写入。

索引与投影按版本和对象修订增量构建。完成报告和共享清单可以流式遍历全量记录，但不在每次任务提交中执行；全量校验另有显式入口。草稿内容查询、进度、问题、冲突和历史全部分页并显示省略信息，不能把响应限制误当成分析覆盖范围。

缓存实行可配置容量与回收策略：区分不可变知识原始记录、可重建材料缓存与可重建索引；回收前检查活动任务/版本引用，不能删除唯一人工修订或运行恢复记录。代码对象不可用时标记证据不可回查，不把缓存丢失解释为重新验证成功。

## 9. 接口与上下文装配

以下为职责草案，具体公开签名随实现确定；读取接口返回版本、来源、确定程度、新鲜度、查询截断与可展开引用。

| 能力 | 职责与限制 |
|---|---|
| memory.query / save / review / history | 只处理长期记忆及候选，按个人/项目、条件、生命周期过滤 |
| knowledge.plan / run / pause / resume | 管理 AnalysisSpec、任务、完成报告和预算，不接受模型自授完成 |
| knowledge.view | 用户与 Agent 两种投影、显式草稿/历史版本选择及分页 |
| knowledge.query / expand / impact / evidence | 只在所选生效版本内查业务知识；影响分析返回有据关系及未知边界，不声称枚举全部影响 |
| knowledge.edit / history / resolveConflict | 无 LLM 的修订保存、幂等/并发校验与合并处理 |
| knowledge.disable / rollback / select | 操作者管理整版停用、回退、固定/自动选择及新鲜度预览 |
| memory.knowledgeLinks / knowledge.memoryLinks | 沿明确引用关联记忆与所选知识版本，不跨权限猜测或合并领域 |
| source.search / read | 原始材料定位与受授权读取；Wiki 未完成时仍可用，但不伪装成正式知识 |
| project.export / import | 显式 Git 文件交换及暂存校验，不自动执行 Git 提交 |

Service 方法不等于模型工具授权。人工保存、接受候选、解决冲突、版本停用/回退/选择、扩额和导入导出仅面向操作者入口；普通 Agent 只能查询和提出候选修订，Wiki Agent 只能按任务权限提交分析结果。若以后开放模型直接编辑，需单独设计明确的授权与审计，不从用户的一次保存或分析许可推导权限。

Host 由注册 Workspace 和当前 Session 解析项目，不接受浏览器传入任意根路径；服务核对项目、视图、版本及对象归属。缺少项目绑定时知识查询返回无项目，不从 Host cwd 猜测；个人记忆仍可按自身权限查询。

默认上下文中“适用记忆”和“项目知识”独立查询、独立配额，再受整个请求的总预算约束；禁止把全库和整本 Wiki 一次性注入。检索结果是带来源的数据，不提升系统提示或工具权限。当前无正式知识时明确返回未就绪，不偷偷查询旧 Card 或草稿；用户显式要求分析草稿时走单独标明 draft 的请求。

两域通过显式的稳定引用关联：至少区分记忆约束的关联实现/测试、决策的关联对象及知识修订的相关经验。引用保存两端 id、关系类型、创建来源和所依据修订；读取再解析当前适用的记忆修订及所选 EffectiveVersion，返回实际使用的双方版本。端点被替代、删除或无法关联时明确提示，不按名称相似度自动连接。仅有关联不代表实现满足要求；“符合/不符合/未知”必须有单独证据或核验结果。

问题涉及规范与现状，或命中对象已有明确关联时，在总预算和可配置展开深度内成组返回两域结果；每次沿边均检查权限、项目范围、敏感性、生命周期与新鲜度，按 id 去重并防止循环展开。内容仍分为记忆要求和知识现状两部分。默认只跨同一项目和当前操作者适用的个人记忆，不借关联扫描其他项目；私有边不进入共享文件。没有可读端点时不能泄漏其标题或私有边是否存在，可公开但已删除/失效的端点则返回状态提示。预算容不下完整组时返回可展开摘要与省略说明，不能只返回一侧便宣称满足约束。

模型实际得到的每个正文、冲突提示和省略说明都通过 DSH 的公开 Session API 写入受访问控制的本地消息，记录精确条目/对象修订、生效版本、Source 向量、新鲜度检查、检索器版本与请求预算。公开接口不等于公开消息或允许 Git 共享；Recall Trace 在原有权限内还原当时内容，不把后续重建索引当作历史召回来源。

## 10. 迁移、实施与验收

### 10.1 旧数据处理

迁移保留记忆候选、接受/拒绝记录、对话提取断点、旧 Wiki Run、证据及人工内容。已接受候选转换为独立长期条目时建立确定的旧到新 id 映射，避免与已经晋升的项目条目重复；没有稳定项目绑定的记录待关联，不能猜测项目。旧 `fact` 记忆保留“历史未分类”，由用户明确归类，不自动改成项目知识。

确定性 AST/目录 Card 归入原始材料导航；已有人工知识卡和旧 Wiki Run 保留历史资料入口及原状态，但不追认它们通过新的业务完成检查。旧 `needs-review` 不直接改名为 completed 或 active。跨 Run 的 slug/Card 幂等关系可作迁移线索，不能作为语义对象身份保证。

数据库迁移在备份和单事务保护下更新单调 schema 版本；未知必需格式拒绝读取，不先删除再尝试重建不可恢复数据。Git canonical 新格式由显式迁移命令预览 diff 后写入，不在普通查询时改写仓库。准备失败保持旧数据可恢复，不实现永久双写或以兼容分支掩盖未迁移状态。

### 10.2 实施依赖

第一条纵切同时落下独立领域和版本基础：长期 MemoryEntry、知识对象/修订、生效指针、编辑及完成报告的数据模型，分离搜索与召回，迁移旧数据且保留当前运行说明。只拆 Tab 不算完成这条产品主线。

第二条纵切建立任务级增量存储、Run 预算、问题清单和跨模块回查，使用包含真实业务条件的本地项目生成语义知识。第三条将双视图、自动激活、无 LLM 保存、基础索引和 Agent 查询一起接通。第四条完成增量合并、分支/多 Source、Git 导入导出和运行恢复验收；这些是完整交付条件，不因最小演示成功而省略。

先以单仓完成上述前三条纵切及基础重分析闭环；分析代际、实际输入审计、人工与过期状态组合、整版停用/回退、记忆详情和明确引用查询属于该闭环的验收，不推迟到上线后。多 Source 和大规模共享按第四条扩展，只有相关验收通过才启用对应能力声明。精确签名、批量文件格式和全局图布局不作为开始单仓实现的前置设计任务。

### 10.3 必须覆盖的正反向验收

| 场景 | 可观察结果 |
|---|---|
| 完整分析与首次使用 | 草稿中途可见；所有检查完成后自动切换双视图，不出现人工批准步骤 |
| 缺读/失败/预算耗尽 | 不能激活，具体缺口可见，成功任务保留且恢复不清零 |
| 已调查未知与源码矛盾 | 允许完成，两个视图与 Agent 均保留未知/冲突，不伪装确定 |
| 两种编辑 | 禁用 LLM 后结构化字段保存与正文保存都成功；后续查询读到新修订，正文涉及的旧关系待复核 |
| 引用与人工修订 | 有效代码位置不能自动证明改后的结论，旧来源留作对照 |
| 并发保存/网络重试 | 旧版本保存拒绝；同请求 id 重试不重复写入；客户端草稿不丢 |
| 激活与保存竞态 | 后台新版本不得覆盖期间发生的人工编辑；投影故障不能让两个 Tab 读到混合版本 |
| 两轮分析乱序 | 同一目标 A 先启动、B 后启动，B 先激活后 A 再完成时指针不回退；B 失败/取消也不自动恢复 A 的资格；重试不递增代际 |
| 分支切换与迟到激活 | A 分支的 Run 在切到 B 后完成，只保存 A 的目标成果；当前选择仍为 B，旧异步评估不能更新 B 的新鲜度 |
| 停用与回退 | 停用后新请求不默认读取该版，重复导入和新生效 id 不绕过停用；回退后的新请求读到保留的人工正文及冲突/过期提示，固定模式阻止后台抢占，旧源码不标 fresh |
| 原文输入与循环证据 | 本地全量读取但仅送摘要、压缩移除原文或发送未确认时不算覆盖；实际输入关联无相关结论可通过；生成对象循环自证不能核验通过 |
| 材料交付与语义质量 | 完整输入记录可以通过交付检查，但与业务 fixture 已知事实矛盾的回答不能通过业务验收；不以已送原文宣称理解正确 |
| 人工修订与过期组合 | 修改 stale 对象仍为 stale，人工说明带旧源版本且不恢复旧关系；无源码依赖的业务补充不因无关文件变化被删除 |
| 重命名/删除/拆分/合并 | 修订延续有据可查，不能匹配的保留待关联，人工删除不能被重新生成复活 |
| 分支与多仓版本 | 两个不同 Source 向量不串用，分支切换和 dirty 工作树不冒充当前已分析 |
| Git round-trip | 私有覆盖不泄漏；部分文件/冲突/未知格式拒绝导入并保留旧版；远端与本地编辑保留冲突 |
| Git 规模与重复导出 | 选定版本的依赖完整，不携带无关中间 Run；未变对象复用，超限停止且不截断；记录多轮增长、checkout/diff 和导入导出成本 |
| 记忆生命周期 | 接受候选形成独立条目；条件冲突成组召回；替代/删除正文退出默认检索，恢复可追溯 |
| 记忆详情与关联查询 | 来源/条件/时间线/最近实际召回可查，搜索命中不冒充注入；幂等约束与实现/测试成组返回，权限和预算不被关联边绕过 |
| 模型可见性与隔离 | 记忆和知识分别装配，可从 Session 重放；无绑定不猜项目，其他项目的 id 不可读写 |
| GB 正文与大文件数 | 内存随批大小而非全目录增长；单任务提交不重写全量；预算/分页/重启正确，未知用量不算零 |

业务验收 fixture 至少包含跨模块入口、配置开关、异步处理、数据状态、异常/重试和测试；多语言材料共同组成一个业务流程，而不是堆放互不相关的 hello-world 文件。固定一组问题、关键事实及可接受的代码证据，用真实 Provider 检查“能回答业务问题并定位实现”，再执行人工纠正、代码变化和重分析，核对保留与冲突。

状态机、并发、隔离与迁移采用 keyless 测试和组装应用快照；真实模型验收保存路由、任务、usage 与产物，不以设置页联通或一份 README 的成功代替业务深度。UI 改动用实际 DSH Web/Electron 流程验证；发布物另验安装、禁用、更新、恢复及卸载。验收记录区分已运行结果与未验证目标，本设计不提前宣称通过。
